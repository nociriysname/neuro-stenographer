# Методика и результаты тестирования

> Подключены диаризация, распознавание и локальная LLM (протокол встречи). Ниже — методика и замеры.

## Метрики (как у организаторов)

| Метрика | Что меряет | Инструмент |
|---|---|---|
| WER | ошибки распознавания слов | `jiwer`, нормализация как у организаторов (уточняется) |
| DER | ошибки диаризации: пропуск, ложная речь, путаница спикеров | `pyannote.metrics` |
| Ошибка границ | среднее отклонение `start_ms` / `end_ms` реплик | свой скрипт |
| RTF | время обработки / длительность записи | тайминги из `ProcessingTimings` |

## Тестовый набор

- Русские диалоги 2–4 человек: свои записи в разных условиях (тихо, шум, перебивания) и открытые корпуса.
- Эталон для каждого файла — JSON в формате ТЗ.

## Порядок прогона

1. Собрать release APK, поставить на тестовое устройство.
2. Прогнать набор в пакетном режиме, получить JSON и тайминги.
3. Посчитать метрики, записать строку на файл в [`artifacts/test-results/results.csv`](../artifacts/test-results/results.csv).

## Результаты

### Диаризация: Nemotron-3-Diarization q8_0, 2026-11-07

Первый прогон, проверка что сборка работает. Метрики посчитаны временным скриптом (кадры 10 мс,
лучшее сопоставление спикеров), не стендом.

- **Устройство:** эмулятор Pixel 9a, arm64-v8a, 4 ядра, хост Apple M5. Реальный телефон будет медленнее.
- **Запись:** синтетический диалог 32.2 с, 16 кГц моно — два голоса macOS TTS (второй со сдвигом тона),
  7 реплик с паузами 0.3–0.9 с. В git не хранится. Длиннее 30.4-секундного буфера `v3-offline`,
  поэтому проверяет и стык окон.
- **Запуск:** `NemotronDiarizerDeviceTest`, debug-сборка (нативный код всё равно `-O2`).

| Метрика | Значение |
|---|---|
| Сегменты / спикеры | 7 / 2, как в эталоне |
| Путаница спикеров | 0 % |
| DER, collar 250 мс | 0.00 % (0.18 % против эталона с обрезанной тишиной TTS) |
| DER, без collar | 9.6 %: ложная речь из-за `pad_onset` и тишина TTS внутри эталонных границ |
| Время диаризации | 1.48 с, RTF 0.046 (без разового копирования модели из assets, 0.16 с) |
| Пиковая память процесса | 256 МБ (VmHWM, вместе с mmap-страницами модели) |

Вывод: сборка и интеграция работают, на чистом диалоге двух голосов модель не ошибается. Синтетика
слишком лёгкая для выводов о качестве: дальше нужны живые русские записи с шумом, перебиваниями и
3–4 говорящими, и замер на реальном телефоне.

### Распознавание: GigaAM-v3, 2026-11-07

Та же запись и то же устройство. Запись распознаётся целиком, без нарезки (`GigaAmSpeechRecognizerDeviceTest`).
WER — после нормализации: нижний регистр, без пунктуации, «ё» → «е», дефис склеивает слова.

| Вариант | WER | Декодирование | Загрузка модели | Пиковая память |
|---|---|---|---|---|
| e2e_rnnt (с пунктуацией) | 2.0 % | 4.36 с, RTF 0.135 | 3.6 с | 489 МБ |
| rnnt | 2.0 % | 2.53 с, RTF 0.079 | 3.2 с | 481 МБ |

Единственная ошибка у обоих — «Барсика» → «Борсика»: TTS так произносит безударную «а». Если дефис
заменять пробелом, WER вырастает до 5.9 %: «нейро-стенографист» распознаётся слитно. Разница в скорости —
единичный замер, без повторов.

`PipelineDeviceTest`: декодирование → Nemotron → нарезка → GigaAM e2e_rnnt → сборка реплик, модели из APK.
LLM ещё не подключена.

|---|---|
| Реплики / спикеры | 7 / 2, все спикеры назначены верно |
| WER | 2.0 % (та же ошибка «Борсика») |
| DER без collar / с collar 250 мс | 2.5 % / 0 % |
| Ошибка границ реплик | в среднем 51 мс на начале и 46 мс на конце, максимум 109 мс |

первый кандидат на ускорение (пункт 8 плана).

### Весь конвейер на стандартном эмуляторе x86_64, 2026-11-08

Так приложение проверяют организаторы: «стандартный эмулятор Android, 4 ГБ». Эмулятор: android-36
google_apis x86_64, 4 ядра, 4 ГБ RAM, хост AMD EPYC (KVM). Гостю видны только SSE4.2/AVX/F16C — без AVX2 и FMA,
поэтому ggml для x86_64 собран без них. Release-логика, модели из APK, `PipelineDeviceTest`.

**Записи.** Живая русская речь: фрагменты подкастов из набора balalaika (эталонный текст есть), собранные в
диалоги по очереди с паузами 0.25–0.9 с. Эталоны и наши JSON — в
[`artifacts/test-results/emulator-x86_64`](../artifacts/test-results/emulator-x86_64). Метрики —
[`tools/metrics.py`](../tools/metrics.py): WER после нормализации (регистр, пунктуация, ё→е), DER с лучшим
сопоставлением спикеров.

| Запись | Длина | Спикеры (эталон / наши) | WER | DER | DER, collar 250 мс | Путаница спикеров | RTF |
|---|---:|---:|---:|---:|---:|---:|---:|
| podcast_mix_1 | 75 с | 2 / 2 | 1.5 % | 6.7 % | 1.1 % | 0 % | 0.220 |
| podcast_mix_2 | 87 с | 2 / 2 | 2.7 % | 5.9 % | 1.4 % | 0 % | 0.213 |
| podcast_mix_3 | 91 с | 2 / 2 | 0.8 % | 2.9 % | 0.4 % | 0 % | 0.238 |

- Время по этапам (mix_1): декодирование MP3 1.1 с, диаризация 5.4 с, распознавание 10.0 с, всего 16.6 с на 75 с аудио.
- DER почти целиком — ложная речь (5–6 %): сегменты диаризации чуть шире речи. Пропусков и путаницы спикеров нет.
- Оговорка про эталон. Изначально в mix_1 и mix_2 было по 3 «спикера» из разных плейлистов, но два из них
  оказались одним диктором (сходство голосов по ReDimNet2+ 0.74 и 0.71 против 0.13–0.26 у разных людей).
  Диаризация нашла по 2 голоса — эталон исправлен, первичные цифры: DER 35 % и 26 % (вся «ошибка» — путаница
  этих двух дикторов).
- Ошибка границ реплик 1–6 с объясняется разной нарезкой: в эталоне подряд идущие фразы одного диктора —
  отдельные реплики, у нас — одна реплика. На записи без таких мест (mix_3) — около 1 с.
- Синтетический голос (espeak-ng) GigaAM почти не распознаёт — для проверки качества нужна живая речь.

**Протокол встречи (LLM)** на тех же записях: 28 с, 28 с и 43 с на эмуляторе. Качество модели протоколов —
в [LLM_PROTOCOL.md](LLM_PROTOCOL.md): на 50 отложенных встречах валидный JSON 49/50, задачи (исполнитель и
срок) — точность 0.85, полнота 0.79.

**Интерфейс на эмуляторе:** онбординг с копированием 1.37 ГБ моделей, открытие MP3 из файлового менеджера
(«Открыть в…»), прогресс по этапам, «Диалог» со шкалой спикеров, экран протокола — скриншоты в
[`artifacts/demo`](../artifacts/demo).
