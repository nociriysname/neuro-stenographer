## Этап 1. Локальная LLM — обязательна по условиям

Без неё решение не соответствует ТЗ. Модель: **Qwen3.5-2B Instruct, Q4_K_M** (1.28 ГБ, Apache-2.0); запасной вариант — Qwen3.5-0.8B, если не уложимся по памяти или размеру APK.

1. Сборка llama.cpp (уже подмодуль, коммит bd4f514) в отдельную `libsteno_llm.so` в `core-llm`: CMake как в `core-diarization`, `-Wl,--whole-archive`, arm64, CPU.
2. JNI-обёртка: загрузка модели через mmap из `ModelInstaller`, генерация с ограничением токенов, отмена через корутины, освобождение памяти после этапа.
3. `LlamaTranscriptPostProcessor`: только пунктуация и регистр. После ответа сверять слова с исходником (нормализация: регистр, ё/е, пунктуация) и откатывать реплику, если слова изменились — WER трогать нельзя.
4. `ModelPack` для весов LLM, чтобы онбординг и настройки учитывали их автоматически.
5. Проверить пиковую память (вместе с ASR не держать: ASR выгружается до LLM-этапа) и время на 10-минутной записи.

**Готово, когда:** на эмуляторе и реальном телефоне конвейер проходит с LLM, WER не растёт, время этапа записано в `TEST_RESULTS.md`.

## Этап 2. Модель данных и хранение

1. В `Transcript` хранить слова с таймкодами (`RecognizedWord`) и сегменты диаризации — они нужны для подсветки слова, дорожек на ленте и воспроизведения реплики. Сейчас после сборки остаётся только текст реплики.
2. Хранилище расшифровок: JSON-файлы в `filesDir/transcripts` (без новых зависимостей) + индекс для списка; `TranscriptRepository` в `core-domain`, реализация в `core-data`.
3. Сохранять расшифровку автоматически по завершении конвейера, вместе со ссылкой на аудио (persistable URI или копия записи).
4. Тесты сериализации и миграции формата (поле `version`).

## Этап 3. Запись с микрофона (экран S03)

1. Foreground service с уведомлением: `AudioRecord` 16 кГц моно → WAV в `filesDir/recordings`; пауза и продолжение.
2. Уровень громкости и волна в реальном времени (`StenoRecordButton`, `StenoWaveform` в стиле Recording, `StenoLevelMeter`), таймер (`typography.timer`).
3. Остановка → экран подтверждения → запуск конвейера на записанном файле.
4. Обработка отказа в разрешении: состояние с иллюстрацией `ErrorMic` и переходом в системные настройки.
5. Новый модуль `feature-record`; кнопка «Записать» на главной вместо заглушки.

## Этап 4. Импорт (S04) и история (S10)

1. Экран подтверждения после выбора файла: длительность, формат, размер, выбор числа говорящих («Авто», 2, 3, 4+). Подсказку числа передать в диаризатор (проверить, какой параметр поддерживает Nemotron).
2. История: список с группировкой по датам, поиск по названию и тексту, мини-шкала спикеров (`StenoSpeakerStrip` малой высоты), удаление с подтверждением (`StenoDialog`), пустое состояние.
3. Нижняя навигация (`StenoBottomBar`): Главная, История, Запись, Импорт, Настройки; главная показывает последние расшифровки и карточку идущей обработки (S02b).
4. Модуль `feature-history`.

## Этап 5. Воспроизведение (S06, мини-плеер)

1. Плеер на `MediaPlayer` в `common-audio` с портом `AudioPlayer` в домене: позиция, скорость 1× / 1.5× / 2×.
2. `StenoMiniPlayer` на экране расшифровки: шкала спикеров со скруббером, нажатие на реплику — переход и проигрывание.
3. Подсветка текущего слова по таймкодам из этапа 2.
4. Пропуск тишины: перескакивать паузы между сегментами диаризации длиннее порога.
5. Лента «Диалога» и плеер синхронизированы: точка воспроизведения на ленте, тап по ленте — перемотка звука.

## Этап 6. Спикеры (S07)

1. Шторка переименования: имя, цвет из 8, «применить ко всем репликам»; хранится вместе с расшифровкой.
2. «Это я»: реплики выбранного спикера справа в «Диалоге».
3. Имена спикеров попадают в экспорт.

## Этап 7. Протокол встречи (S08)

1. Промпт для LLM: краткое содержание, решения, поручения с ответственными; длинные записи — по частям с последующим объединением.
2. Пункты протокола ссылаются на таймкоды (переход к реплике).
3. Копирование и экспорт протокола; честная пометка «сгенерировано локальной моделью».

## Этап 8. Экспорт (S09) до конца

1. VTT; переключатели «имена спикеров» и «таймкоды»; «Поделиться» через `ACTION_SEND`.
2. Проверка JSON на точное соответствие формату организаторов (`speaker_id`, `start_ms`, `end_ms`, `text`) — автотест на эталонный файл.

## Этап 9. Скорость (RTF)

1. Замеры по этапам на реальном телефоне (не только эмулятор): декодирование, диаризация, ASR, LLM.
2. Параллельность: ASR фрагментов начинать по мере готовности сегментов диаризации; декодирование аудио — потоково.
3. Подбор потоков ONNX Runtime и ggml под big.LITTLE; проверить XNNPACK / NNAPI для GigaAM.
4. Обновлять таблицу RTF в `TEST_RESULTS.md` и `artifacts/test-results/results.csv` после каждой оптимизации.

## Этап 10. Эмоции — wow-фича для защиты

1. Выбрать компактную модель распознавания эмоций по голосу с лицензией, допускающей использование, и ONNX-экспортом; оценить скорость.
2. Классы: нейтрально, радость, раздражение, грусть, удивление (`EmotionTone` в uikit уже есть).
3. UI по концепции «Ленты разговора»: метка `StenoEmotionTag` у реплики, отметки на ленте, лёгкая тонировка; флаг в настройках уже сохраняется.
4. В интерфейсе и на защите подавать как подсказку, а не оценку человека.

## Этап 11. Качество и замеры

1. Прогнать WER и DER на данных организаторов (скрипты `wer.py`, `der.py` перенести в `tools/`), нормализация чисел, дефисов и ё — по ответу организаторов.
2. Длинные записи (60+ минут): память, время, корректность склейки фрагментов на границах.
3. Шумные записи и перекрывающаяся речь: оценить и описать в `LIMITATIONS.md`.

## Этап 12. Полировка UI и технический долг

1. Перенести в uikit то, что фичи собрали сами: отключённое состояние `StenoOptionCard`, квадратная кнопка 64 dp из онбординга.
2. Проверить все экраны при ширине 360 dp, крупном системном шрифте (200 %), в тёмной теме и с TalkBack.
3. Compose UI-тесты для ключевых сценариев (онбординг, импорт → расшифровка → экспорт).
4. Просмотреть превью всех компонентов и сверить с макетом.

## Этап 13. Сдача

1. Release-сборка APK с подписью, проверка установки на чистое устройство без интернета.
2. Документация: README (статус, запуск), `ARCHITECTURE.md`, `TEST_RESULTS.md`, `LIMITATIONS.md`, лицензии моделей и шрифта.
