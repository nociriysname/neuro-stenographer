# Формат вывода и контракт конвейера

> В шаблоне организаторов этот файл описывал акустический протокол прошлого хакатона.
> Для нашей задачи «протокол» — это формат результата и контракт этапов обработки.

## Цели

- Выдавать расшифровку ровно в том формате, по которому эксперты считают метрики.
- Зафиксировать, что каждый этап конвейера получает и что отдаёт, чтобы движки можно было менять
  независимо друг от друга.

## Формат выходного JSON (ТЗ, стр. 15)

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

| Поле | Тип | Правило у нас |
|---|---|---|
| `transcript` | array | Реплики отсортированы по `start_ms` |
| `speaker_id` | string | `speaker_N`, N с 1 по порядку первого появления в записи |
| `start_ms`, `end_ms` | integer | Мс от начала файла; начало первого и конец последнего слова реплики |
| `text` | string | UTF-8, без экранирования кириллицы |

Лишних полей в JSON нет: имена говорящих, саммари и метрики показываются только в UI.
Сериализация — `core-data/.../TranscriptFormatter.kt`. Тест сверяет вывод с примером из ТЗ побайтно.

Дополнительно экспортируются TXT (`[00:00:01.250 – 00:00:04.380] speaker_1: текст`) и SRT.

## Контракт этапов

| Этап | Порт в `core-domain` | Вход | Выход |
|---|---|---|---|
| Декодирование | `AudioRepository` | `AudioRef` (content:// URI) | `PcmAudio`, моно float, 16 кГц |
| Диаризация | `Diarizer` | вся запись | `SpeakerSegment(speaker, startMs, endMs)`, могут перекрываться |
| Нарезка | `ChunkPlanner` | сегменты, длительность | фрагменты ≤ 20 с с границами в паузах |
| ASR | `SpeechRecognizer` | фрагмент + `offsetMs` | `RecognizedWord(text, startMs, endMs)` с абсолютным временем |
| Сборка | `TranscriptAssembler` | слова + сегменты | `Transcript` |
| Постобработка | `TranscriptPostProcessor` | `Transcript` | `Transcript` с теми же словами (меняются только пунктуация и регистр) |

## Ошибки и восстановление

- Движок не готов или упал при загрузке → `EngineUnavailableException`, экран показывает причину и
  кнопку «Повторить».
- LLM упала → расшифровка отдаётся без постобработки, в UI показывается предупреждение.
- Диаризация не нашла речь → ASR всё равно проходит по всей записи фрагментами по 20 с.
- Файл без аудиодорожки или без декодера на устройстве → `UnsupportedAudioException` с понятным текстом.
