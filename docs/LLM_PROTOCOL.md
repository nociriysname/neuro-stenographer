# Локальная LLM: протокол встречи

Локальная LLM в приложении составляет **протокол встречи** по готовой расшифровке: краткое содержание, принятые
решения, задачи с исполнителем и сроком, ключевые факты (экран S08). Текст расшифровки она **не меняет**:
организаторы просили оставлять его дословным, его сравнивают с эталоном по WER.

## Модель

| | |
|---|---|
| База | [LiquidAI/LFM3-1.7B](https://huggingface.co/LiquidAI/LFM3-1.7B), русский язык поддерживается, 1.7B параметров |
| Дообучение | LoRA r=32 на все линейные слои, 2 эпохи, 4500 примеров (см. ниже), 2× RTX 4090, ~35 мин |
| Формат на устройстве | GGUF Q4_K_M, 1.1 ГБ, llama.cpp (CPU); веса — [Den4ikAI/LFM3-1.7B-meeting-protocol-ru-GGUF](https://huggingface.co/Den4ikAI/LFM3-1.7B-meeting-protocol-ru-GGUF), скачивает `tools/fetch_models.sh` |
| Промпт | шаблон чата LFM3 с выключенными рассуждениями (`<think></think>`), расшифровка строками `спикер_N: текст` |
| Ответ | компактный JSON `{title, summary, decisions[], tasks[{task, assignee, due}], key_points[]}` |
| Декодирование | жадное + штраф за повторы 1.1 на последних 64 токенах (без него модель изредка зацикливается) |

Почему не взяли модель «как есть». Небольшие модели без дообучения на этой задаче не годились: Qwen3.5-0.8B
выдумывала факты, Qwen3.5-4B составляла приличный протокол, но для телефона тяжела; классификаторы
(FRIDA-Decisions, openjev) находили решения в 8–14 случаях из 16, при 1.2–9 ГБ весов. LFM3-1.7B без дообучения
давала валидный JSON в 37 из 50 случаев и почти не попадала в исполнителей и сроки (точность 0.05).

## Данные

Своих размеченных протоколов не было, поэтому набор синтетический (`tools/llm/`):

1. `gen_meetings.py`, `gen_podcasts.py` — gpt-6.1 (через Codex CLI) пишет реалистичные расшифровки и эталонные
   протоколы к ним. Каждый вызов получает случайный сценарий: сфера (40 вариантов, от ИТ-стендапа до
   оперативного совещания смены АЭС и совета котов Котовицы), формат встречи, 2–5 спикеров, длина 8–55 реплик,
   есть ли решения, сроки и имена, уровень «шума распознавания» (ослышки, склейки слов, числа словами — как
   на выходе ASR). Всего 1800 встреч и 500 подкастов/интервью, ни одного сбоя генерации.
2. `build_sft.py` — из каждого диалога делает протокол целиком и ещё одну «узкую» задачу (только краткое
   содержание, только задачи или только решения): одна модель, тип выжимки задаётся инструкцией.
3. 50 встреч отложены для проверки (`eval_ids.json`) и в обучение не попадают.

Набор лежит в `tools/llm/synthetic_dialogs.jsonl.xz` (2300 диалогов). Обучение — `train_lora.py`, оценка —
`eval_lora.py`, примеры ответов — `show_examples.py`.

## Качество (50 отложенных встреч, жадное декодирование)

Задача засчитывается, если совпали и исполнитель, и срок (без учёта регистра и пунктуации).

| Модель | Валидный JSON | Задачи: точность | Задачи: полнота | Решений найдено (эталон 108) |
|---|---:|---:|---:|---:|
| LFM3-1.7B без дообучения | 37/50 | 0.05 | 0.08 | 160, много лишнего |
| + LoRA, 1000 встреч | 49/50 | 0.81 | 0.76 | 90 |
| **+ LoRA, 1800 встреч + 500 подкастов (в приложении)** | **49/50** | **0.85** | **0.79** | **100** |

Квантизация в Q4_K_M качество не ухудшила: на 12 примерах точность и полнота 0.81 / 0.75 против 0.79 / 0.75 у bf16.

Типичные ошибки дообученной модели: путает роли в кратком содержании («Ольга рассказала» вместо Марины),
местами неудачная формулировка задачи, редкие грамматические огрехи. На бессвязном входе (склейка обрывков
разных историй) может досочинять детали — поэтому на экране есть плашка «проверьте формулировки», а на
записях с речью меньше 25 слов протокол не составляется вовсе.

## Скорость

| Устройство | Чтение промпта | Генерация | Протокол встречи 1.5–3 мин |
|---|---:|---:|---:|
| Хост, 4 ядра EPYC с AVX2 | ~100 ток/с | ~13 ток/с | 30–40 с |
| Эмулятор x86_64, 4 ядра, 4 ГБ (без AVX2) | — | — | 18–43 с |

Пик памяти с отключённой перепаковкой весов (`use_extra_bufts = false`) — около 1.3 ГБ, контекст 4096
токенов. Модель загружается на время генерации и сразу освобождается; в памяти одновременно не бывает
LLM и моделей расшифровки.

## Длинные записи

Расшифровка режется по репликам на части до 2200 токенов (обучение шло на диалогах до ~2.5 тыс.).
Протокол строится для каждой части, затем списки решений, задач и ключевых фактов объединяются без повторов,
краткие содержания идут подряд.

## Сборка

llama.cpp подключён отдельным сабмодулем `src/android/third_party/llama.cpp-llm` (у диаризации свой, закреплённый
на коммите NeMo-Speech.cpp, а архитектура LFM3 появилась позже) и собирается в `libsteno_llm.so`
(`core-llm/src/main/cpp`). Символы ggml в обеих библиотеках скрыты (`--exclude-libs,ALL`), две копии не
конфликтуют. Для x86_64 ggml собирается без AVX2/FMA: стандартный эмулятор Android их гостю не отдаёт.
